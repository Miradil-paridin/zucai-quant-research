# 页面与交互设计

## 1. 设计方向：夜场分析台

首版采用深色专业研究界面，不使用体育博彩常见的高饱和促销视觉。深海军蓝作为基础表面，青色用于模型信息，黄绿色只用于通过验证的正向信号，琥珀色用于不确定性与告警。

界面以“一个问题，一个主操作”为原则：当前比赛是否存在经得起数据质量和模型校准检查的价值差？主操作固定为“加入模拟观察”，不提供真实投注按钮。

## 2. 信息架构

| 路由 | 核心问题 | 主要内容 |
|---|---|---|
| `/` | 今天有哪些比赛值得研究？ | 联赛筛选、赛程、数据完整率、模型状态 |
| `/matches/:id` | 这场比赛是否存在可靠价差？ | 1X2 概率、赔率漂移、驱动因素、风险闸门 |
| `/players` | 球员状态和稳定性如何变化？ | 位置评分、5/10/30 场曲线、置信度 |
| `/teams` | 球队强度正在向哪个方向移动？ | 攻防、中场、门将、状态和赛程密度 |
| `/backtest` | 模型在样本外是否可信？ | ROI、CLV、回撤、校准图、联赛集中度 |
| `/ops` | 数据链路是否健康？ | 延迟、缺失、冲突、Schema 漂移、作业状态 |

## 3. 比赛分析台布局

```text
┌──────────┬──────────────────────────────────────────────────────┐
│ 主导航   │ 日期 / 时区 / 阶段 / 数据新鲜度                     │
├──────────┼──────────────┬───────────────────────────────────────┤
│          │ 今日比赛列表 │ 选中比赛：球队、开赛时间、状态        │
│          │              ├──────────────────┬────────────────────┤
│          │              │ 模型 vs 市场概率 │ 赔率漂移            │
│          │              ├──────────────────┴────────────────────┤
│          │              │ 关键驱动因素 / 阵容影响 / 赛程疲劳    │
│          │              ├──────────────────┬────────────────────┤
│          │              │ 模型解释          │ 风险闸门与模拟操作    │
└──────────┴──────────────┴──────────────────┴────────────────────┘
```

## 4. 交互规则

- 切换比赛：概率、赔率曲线、驱动因素和风险闸门同步更新。
- 联赛筛选：只影响左侧比赛列表，不重置已选比赛，除非已选项不在结果中。
- 查看解释：展开结构化解释，不生成超出输入数据的数值。
- 加入模拟观察：写入本地演示状态；真实版本调用审计 API，操作可撤销。
- 风险闸门：任一关键项失败时禁用模拟操作，并展示最接近通过的条件。
- 图表悬停：显示 UTC 捕获时间、本地时间、来源与快照类型。

## 5. 视觉令牌

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#07100f` | 主背景 |
| `--surface` | `#0d1816` | 次级表面 |
| `--surface-raised` | `#12211e` | 少量抬升区域 |
| `--text` | `#edf7f2` | 主文字 |
| `--muted` | `#81928c` | 次级文字 |
| `--cyan` | `#59d5d0` | 模型与信息 |
| `--lime` | `#b7f36b` | 通过、正 edge |
| `--amber` | `#f3b95f` | 不确定性 |
| `--danger` | `#ff7a82` | 阻断性异常 |

圆角只用于可操作控件和真正独立的对象；主要分区依赖留白、对齐和轻量分隔线。正文 14–16px，数字使用等宽字体以便比较。

## 6. 响应式策略

- `>= 1280px`：三列分析台完整展示。
- `960–1279px`：比赛列表收窄，风险闸门移到主内容下方。
- `< 960px`：侧栏变为顶部导航，比赛列表水平滚动，图表单列。
- `< 640px`：保留概率、风险与主操作，隐藏次要诊断信息。
