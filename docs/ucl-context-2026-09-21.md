## 完成范围与实际缺口

- 18份UEFA正式战术名单，396条首发记录（出场记录，不是跨比赛去重球员数）。全部重新解析PDF，验证文件SHA-256、比赛日期、球队标题及双方各11人，与入库数据一致。
- 41个引用来源，包括18份正式名单，以及俱乐部、UEFA、媒体的报道。每个来源保存URL、页面日期、核对时间和来源类型。PDF额外保存下载时间与原文件哈希；媒体文章是人工查阅后的结构化摘录，没有声称保存了全文历史快照。
- 126条伤停／停赛／注册／恢复／球队层面可用性报道，不能称为126名伤员。35支球队有部分报道，矿工本场完整伤停仍未知。已查阅矿工官方赛前训练报道，内容没有给出缺席名单，因此不填“无伤停”。
- 5条赛前存疑记录补充了正式首发状态，保留原说法：Hadj Moussa、Undav、Alvarez、Zima、Udol。名单能证明被列为首发，不能证明完全健康或可以踢满90分钟。
- 18场均有基于已采资料的定性分析；其中5场有明确的赛后观察来源。其余战术判断属于待事件／视频数据检验的推断，没有伪装成已观测的比赛机制。

**这是一批历史研究资料，不是18份赛前预测。** 所有条目都标记为`historical_backfill`、`point_in_time_verified=false`、`eligible_for_prediction_backtest=false`。本批没有补写任何预测、提高命中率或生成调整后的胜率。已有市场概率计算保持原逻辑。

## 存储与复核

结构化研究文件：`data/research/ucl-2026-27-md1-context.json`。本篇对应初次阵容研究版本`2026-09-21-v2`，当前文件已扩展至v3；数据库保留导入过的早期版本，修订新增版本，不覆盖旧档。

数据库表：`analytics.context_batches`保存版本、完整来源和内容哈希，`analytics.match_context_dossiers`关联真实比赛。导入以football-data.org的比赛ID、双方球队ID、开赛时间和已完赛赛果做严格对应。18场先全部校验，再在一个事务中写入；同版本重复导入无变化，同版本内容修改被拒绝。两张表均禁止UPDATE/DELETE。

运行命令（工作目录为项目根目录）：

```powershell
backend/.venv/Scripts/python.exe -X utf8 backend/scripts/verify_ucl_context_sources.py
backend/.venv/Scripts/python.exe -X utf8 backend/scripts/import_ucl_context.py --validate-only
backend/.venv/Scripts/python.exe -X utf8 backend/scripts/import_ucl_context.py
```

原始PDF保存在忽略提交的`output/research/ucl-context/`。在新机器可给验证脚本加`--download`获取缺少的PDF；若远端文件变更导致哈希不同，会停止并要求人工复核，不静默覆盖研究版本。验证报告为该目录下的`verification.json`。

## 下一阶段需要的数据

1. 对未来比赛，在真实赛前保存来源快照和采集时间，再于确认首发时更新；这才能形成能检验的赛前样本。
2. 补充球员稳定ID、近期开场／替补分钟、通常担任位置、替代者水平，避免按伤停人数粗略加减分。
3. 统一事件／预期进球数据口径，验证上述战术假设；不能用新闻叙述代替事件指标。
4. 累积多轮、多赛季样本，按时间切分，与现有市场概率基线对照检验校准、Brier和Log Loss。只有通过独立检验，才考虑启用阵容概率调整。

18场足够作为首批资料核对和分析流程样本，不足以训练或证明可靠胜率。当前页面的用途是提供可追溯的辅助参考。
